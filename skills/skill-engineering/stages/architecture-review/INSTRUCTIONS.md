# Architecture Review 阶段

[返回文件地图](../../references/file-map.md) · [架构声明与门禁规范](../../references/architecture-review.md)

用于所有已有 Skill 维护，包括小修、扩展、重构或维护规划。全新创建继续 Native Authoring，不要求已有目标或历史基线。这个目录是内部 workflow step，不新增顶层 Skill 身份。

1. 读取上方单一规范与已有产品、架构、当前任务；复用能力探索结论，确认本轮归属和范围。普通小修只做轻量裁决，不复制完整项目模板。
2. 写清需求、归属与理由、旧结构保留/替换/退役说明、受保护行为及边界变化；决策需要拆分或延后时停止当前候选应用并给出下一步。
3. 在独立候选修改。根据原目标、overlay 与显式删除清单恢复完整候选；原候选缺失的文件默认保留，不能据此自动退役。
4. 读取工具计算的实际指纹、累计指标、有效整体基线与开放债务；按规范判断整体门是否触发，不把最近的局部维护当成新整体基线。
5. 整体门触发时，由候选生成者之外的独立评审者检查完整候选六项边界，形成绑定实际指纹的证据。声明不能代替真实行为测试或证明评审身份。
6. 按规范生成脱敏声明，交给现有 improve 预览。分别核对本次维护完成门、整体架构完成门、历史覆盖限制及累计债务；未知事实保留为未知。
7. 把最终预览交回原 Review 阶段；经批准只应用同一计划，再运行原 postflight、Verify 与安全恢复流程。
8. 返回本轮结果、整体架构状态、证据限制和唯一下一步。缺声明或旧未审查计划按规范阻断，补审后重新预览；历史记录仍可查看及安全恢复，不能把历史未审查包装为通过。
