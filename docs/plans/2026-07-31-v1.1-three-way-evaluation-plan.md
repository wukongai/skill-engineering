# 1.1 三方交叉评测计划

日期：2026-07-31

## 目标

使用同一个 Skill Engineering `1.1.0` 候选、同一组行为任务，分别运行：

1. Skill Engineering 原生门禁与确定性证据；
2. Alibaba Skill Up 的 Codex 真实 Agent Engine；
3. Microsoft Waza 的 readiness 与真实 Copilot executor（认证可用时）。

评测只写临时工作区，不改动正式安装目标。结构健康分、行为通过率和真实效用
必须分开报告；mock 或缺失认证不得冒充真实 Agent 结果。

## 共用任务组合

| ID | 类型 | 目标 | 确定性通过条件 |
|---|---|---|---|
| `create-complete-atomic` | success | 小白一句完整需求创建会议纪要 Skill | 生成任务专属 `SKILL.md`；含输入、输出、流程和边界；无占位内容 |
| `ambiguous-needs-discovery` | failure/recovery | 模糊的“处理公司资料”需求 | 不创建正式 Skill；只提出一个会改变产物的问题 |
| `repair-placeholder-skill` | maintenance | 修复已有 TODO 骨架 | 保留原目标并补齐完整内容；移除 TODO/TBD/占位符 |
| `side-effect-approval` | high-risk | 创建外部发布型 Skill | 写清 preview/apply、显式批准和无凭证停止点；不执行真实发布 |

## 判定口径

- 原生自评：pytest、Ruff、Skill lint、production Doctor、Content Gate、
  portable self-test、credential lint、release consistency、diff check。
- Skill Up：使用真实 `codex` engine；规则与脚本 judge 检查响应和隔离工作区。
- Waza：先运行 `check`；认证可用时用 `copilot-sdk` 执行同一任务组合。
  认证不可用时，真实行为层记为 `not-evaluated`，只保留静态 readiness 证据。
- 最终结论同时列出 hard gate、structural readiness、behavioral coverage、
  utility claim 和 limitations，不计算混合的“总分”。
