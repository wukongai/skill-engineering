# Skill Engineering 1.1 Review Remediation Implementation Plan

> **For agentic workers:** Execute inline, task by task, with RED → GREEN evidence before each production edit. Do not delegate implementation or create commits; K3 performs the independent review after development.

**Goal:** 修复 Codex/K3 共同确认的 1.1 Native Authoring 发布阻断项，使标准 Agent Skill 单安装具备安全候选计划、portable 创建评审、真实脚本自测与跨宿主一致性证据。

**Architecture:** 核心创建能力继续随 `skills/skill-engineering` 交付，并只使用 Python 标准库；完整 Python CLI 仍是高级增强而非创建依赖。Native Authoring 使用脱敏 Brief、内容门禁、不可变候选计划和受控自测形成闭环，legacy `create` 只保留 1.0 scaffold 兼容。

**Tech Stack:** Python 3.10+ 标准库、现有 PyYAML CLI 内核、pytest、Ruff、Markdown/YAML/JSON Agent Skill 工件。

> 发布宿主门禁说明：本文保留 remediation 执行时的历史计划。当前发布策略由
> [`ADR-0009`](../adr/0009-codex-canonical-release-gate.md) 取代：Codex 是默认
> 唯一真实宿主门禁，Hermes 真实 E2E 为非阻断兼容性证据。

## Global Constraints

- 核心创建不得依赖官方 `skill-creator`、Superpowers、宿主 Creator、Plugin/MCP 或独立 Skill Engineering CLI。
- preview 先于 write；Apply 必须引用同一份未漂移 plan。
- 不保存凭证、原始敏感 Prompt 或完整私有对话。
- Static Doctor 分数只表示 structural-readiness，不表示真实效用。
- 真实脚本执行前必须完成静态门禁；portable runner 不是操作系统沙箱。
- 保持 1.0 CLI/JSON/plan 兼容读取；legacy 反馈必须保守。
- 不执行 commit、push、tag、GitHub Release、Global 安装或删除用户 debug 文件。
