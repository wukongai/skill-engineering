## 3. Critical

### C1 — R5 parity 要求按现写法会制造不可维护的“第二套评分模型”

- 位置：Spec R5（`:123-130`）“PASS/FAIL 一致、grade 一致、总分差为 0、四维分数一致”。
- 问题：全量“总分差为 0”parity 只有两条路——(a) 在 `creation_review.py` 里重写 Doctor v2 评分逻辑（双实现漂移，正是 ADR 0008 与 1.1 Spec 禁止的第二套评分模型）；(b) 两套实现共享规则定义，但 Spec 没有给出共享机制。而完整 Doctor 比 portable 子集多出 contract/evaluation/provider 规则，只要这些规则扣分，两边总分天然不等，“总分差为 0”无法稳定成立。
- 为什么影响核心目标：CR-03 的修复如果以不可维护的双实现为代价，会把“单安装可评审”换成“评分模型腐化”，是 1.1 明令防止的架构倒退。
- 最小修订：把 R5 改写为——**portable creation review 是 Doctor v2 评分 rubric 的 portable profile**：共用同一维度、权重（20/25/25/30）与等级阈值；规则集是显式枚举的可移植子集（frontmatter、触发边界、资源入口、副作用审批、失败处理、安全文本扫描）。parity 只承诺**枚举 fixture 集**上的 status/grade/四维一致（fixture 清单进仓库），不作全称“总分差 0”；完整 CLI Doctor 作为可选增强，其额外规则差异通过 assessment coverage 明示。parity fixture 即是防漂移机制。

### C2 — R2 未声明 plan 的威胁模型与 hash 排除字段

- 位置：Spec R2（`:44-76`）。
- 问题一：计划把“创建评审摘要、applied/verified 状态与时间”存入 plan，但 preview 在写入前生成——这些字段必然在 apply/verify 时变化。若不显式声明哪些字段不参与 plan_hash，就会重新制造 CR-06 同构的歧义。
- 问题二：plan 是宿主可写的 JSON，fingerprint 只能防**漂移**，不能防**篡改**（写者可重算哈希）。这与 1.0 BuildPlan 的信任模型一致（宿主 Agent 是受信执行者），但 Spec 没有明说，容易让评审者误判安全等级。
- 最小修订：R2 增加两条——(1) 显式列出 plan_hash 排除字段（applied、verified、review summary、时间戳）；(2) 声明威胁模型：防漂移不防篡改，宿主 Agent 为受信执行者；临时目录使用 `mkdtemp` 唯一命名。

## 4. Important

### I1 — R8 “必须不同”会强制人工分叉

- 位置：Spec R8（`:184`）“每个 adapter 的 target、写入工具和审批字段必须不同”。
- 问题：Codex 与 Kimi CLI 在我的 fixture 中共享 `.agents/skills` 与 host_file_edit 是**事实正确**的相同；要求“必须不同”会逼 adapter 编造差异，与 Case E“只有真实宿主差异才适配”的原意相反。
- 最小修订：改为“各字段必须符合各自 adapter reference；允许能力相同的宿主取值相同，差异性断言只针对确实不同的宿主（如 Hermes 的 skill_manage 与 pending/diff/approve）”。

### I2 — R6 未声明 portable runner 的残留风险

- 位置：Spec R6（`:132-165`）。
- 问题：临时副本 + 环境清理 + timeout 是好的，但 runner 以用户权限运行、**无网络限制、无子进程限制、无 CPU/内存限制**。Spec 要求“指出仍可能存在的风险及最小可接受控制”，目前文本只给了控制、没有给残留风险声明。
- 最小修订：增加一段——1.1 portable runner 不是沙箱：网络与子进程不阻断；缓解依赖执行顺序（Content Gate 与 Doctor SEC 静态扫描先于自测）+ manifest 只允许候选内脚本 + 临时副本 + timeout；高风险 Skill 必须先过 SEC 门禁。非 Python 声明脚本：manifest 不支持时报告“未覆盖”，不得静默跳过。

### I3 — R4/R6 “纯 Agent Skill 必须有行为样例”与“不需要的目录不创建”冲突

- 位置：Spec R6（`:165`）。
- 问题：“没有脚本的纯 Agent Skill 可以省略 manifest，但必须有至少一个行为样例”若理解为强制 `tests/` 目录，与 `authoring-standard.md`“不需要的目录不创建”直接冲突。
- 最小修订：澄清行为样例可以是 `SKILL.md` 内的示例段或 Brief `examples`，不强制 tests 目录；只有声明脚本时才强制 self-test manifest。

### I4 — CR-03 修复缺少 `creation-review.md` 主路径更新验收项

- 位置：Spec R5 隐含替代，但未列出文档交付物。
- 问题：不更新 `references/creation-review.md` 与 `doctor_skill.py` 的退出 2 文案定位，修复后文档仍写着“运行 Doctor v2 评审”为主路径，CR-03 只修了一半。
- 最小修订：验收条件增加——`creation-review.md` 改为 portable creation review 主路径、完整 CLI Doctor 为可选增强；`tests/test_doctor_wrapper.py` 的退出 2 期望仅保留给完整 Doctor 场景。

### I5 — R2 的 `--brief <brief.json>` 入口可能绕过脱敏边界

- 位置：Spec R2（`:49`）。
- 问题：接受任意 brief.json 路径，就允许传入未经过 `save_authoring_brief()` 脱敏边界的文件。
- 最小修订：改为 `--brief-id` 引用 `.skill-engineering/authoring-briefs/` 中已持久化的脱敏 Brief，plan 记录其 id 与 fingerprint；不接受游离 JSON。
