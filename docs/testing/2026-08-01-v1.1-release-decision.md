# v1.1.0 正式发布决策

日期：2026-08-01  
决策：批准按已冻结候选发布 `v1.1.0`；发布后立即启动独立的正式 Tag 用户回归。

## 为什么允许先发布

`v1.1.0` 不是未经验证的开发快照。发布前已具备以下证据：

- Codex 无 Creator 真实 E2E 已完成从失败、修复、同一 Native Plan Apply/Verify
  到真实样本 `validated` 的闭环；
- K3 remediation 终审结论为 `approved`；
- Alibaba Skill Up 驱动的真实 Codex 四个核心场景 4/4 通过；
- 212 项 pytest、Ruff、Skill validation、production Doctor 100/A、
  portable self-test、credential lint、release consistency 和 diff check 全绿；
- Codex 是 ADR-0009 规定的唯一必须通过的真实宿主门禁，其他宿主实测是
  非阻断兼容性证据。

与不完整的旧版相比，继续延迟 `v1.1.0` 会让公开用户继续获得已经确认不满足
“单安装完整创建”目标的版本。Owner 因此明确批准先发布已经冻结并通过门禁的
候选。

## 明确延后的证据

本次没有在正式发布前完成下面这一整段用户旅程：

1. 从远程正式 `v1.1.0` Tag 安装到一个全新隔离项目；
2. 以普通用户的模糊需求开始，通过逐步澄清生成一个全新 Skill；
3. 完成 Preview、明确批准、Apply、结构验证和真实任务试用；
4. 制造一个真实失败，再通过独立候选完成修复、回归和维护记录；
5. 验证远程安装物与发布提交一致，并记录可复现证据。

这项证据只能在正式 Tag 可用后完整执行，因此转入独立的发布后用户回归项目。
它不影响已完成的发布前工程门禁，但在完成前必须公开保留以下限制：

- 不宣称已经覆盖所有新手工作方式、Agent 宿主和生产环境；
- Doctor `100/A` 只表示结构准备度，不表示业务效用；
- adapter contract fixture 不等于非 Codex 宿主的真实 E2E。

## 发布后回归结果

这项延后证据已于 2026-08-01 在全新独立 Codex 项目完成。结论为
`passed_with_limitations`，无阻断问题：

- 从公开精确 Tag `v1.1.0` project-local 安装，并核对 annotated tag 与发布提交；
- 从普通用户模糊需求完成逐轮 discovery、完整候选、Preview、同 plan Apply/verify；
- 17 条合成 Markdown/CSV 反馈完成证据、去重、冲突、P0–P3 与未知项验证；
- 未授权 Slack 自动发送候选命中安全硬门禁，正式 source 零漂移；
- 收窄为只读草稿后完成维护记录、真实 undo 和最终重应用。

完整报告见
[`2026-08-01-v1.1-post-release-user-regression.md`](2026-08-01-v1.1-post-release-user-regression.md)。
结论仍只覆盖本次 Codex 场景，不扩展为所有宿主或生产外部集成已验证。

## 发布与回退

- 发布提交、`v1.1.0` annotated tag、GitHub Release 和 Gitee tag 必须绑定同一
  代码状态；
- 发布附件必须从该状态构建并通过干净环境安装 smoke；
- 若发布后回归发现阻断问题，先停止推荐 `v1.1.0`，记录可复现失败，再按
  patch 版本修复；不得静默改写既有 tag；
- Commit、Push、Tag、Release 已由 Owner 在 2026-08-01 明确授权；
  Global/Profile 自动安装仍未授权。
