## 5. Authoring Brief 与架构判断

Brief：`.skill-engineering/authoring-briefs/customer-feedback-triage-v1.json`

必填字段：

- `goal`：本地 Markdown/CSV 客户反馈的证据化去重、归类、P0–P3 分级和产品建议；
- `positive_triggers`：整理本地客户反馈并给出优先级；
- `negative_triggers`：自动发 Slack、修改工单、登录后台；
- `verification`：Content Gate、portable review、自测和至少 12 条真实样本。

架构结论：轻量 `atomic` Skill + 一个 Python 标准库只读归一化脚本。

未选择其他方案：

- 一次性 Prompt：无法稳定复用证据、去重和 P0 边界；
- 纯 Script：不能可靠承担语义归类、矛盾解释和产品建议；
- Plugin/runtime：第一版不需要账号、鉴权或外部系统，增加它会扩大安全面。

治理：personal，project-only；通过 contract 和 regression case 为未来团队升级留出路径。

## 11. 问题清单

### 阻断问题

无。

### 非阻断问题

1. **标准 Skills 安装不包含 Python CLI runtime。**

   这是 Tag README 明确披露的 1.1 边界。创建主链路使用随 Skill 交付的 portable scripts 完成；深度维护通过同一 Tag 官方 runtime 临时运行：

   ```text
   git+https://github.com/wukongai/skill-engineering.git@v1.1.0
   ```

   uv 实际解析到 `1f6508db4ad5ace606f739f7ec2329d671beb109`，与 Tag 解引用一致。未安装 Global/Profile Skill。

2. **`uvx --offline` 不能用 Tag 名重新解析缓存。**

   离线 Tag 名失败后改用已验证的精确 commit，避免网络漂移。属于 uv 缓存解析限制。

3. **完整 Doctor 仍有 3 个 WARN，得分 82/B。**

   不阻断 personal profile；见第 10 节。没有为了追求分数把无关结构债务混入 Slack 草稿维护。

4. **标准 CLI list 对 `.agents/skills` 展示多个兼容 agent。**

   安装命令限定 Codex，scope 是 project；显示行为可能让新手误以为为多个宿主做了独立安装。

5. **Portable self-test 不是操作系统沙箱。**

   runner 报告 `sandbox=false`，但有 static gate、manifest allowlist、临时副本、最小环境和 timeout。

6. **非 Codex 宿主未评估。**

   这是本次明确范围边界，不应推广结论。

7. **真实 Slack/工单/账号集成未评估。**

   按只读安全边界故意不测试；只验证了未授权集成被阻断和草稿不发送。

## 14. 最终判定

`passed_with_limitations`

理由：

- 所有核心 Codex 用户链路、安全阻断、真实样本和恢复链路通过；
- 没有阻断问题；
- 仍需披露标准安装不包含深度维护 runtime、完整 Doctor 的 3 个 WARN、通用 agent 列表显示、portable runner 非 OS sandbox，以及非 Codex/真实外部集成未覆盖。

该结论可以回填主项目作为 `v1.1.0` 发布后 Codex 用户回归证据，但不能推广为所有宿主、所有输入或生产外部集成已验证。
