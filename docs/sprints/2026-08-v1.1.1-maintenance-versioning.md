# Sprint：v1.1.1 Maintenance Tiers & Versioning

状态：In Progress（Spec/Plan pending）/ Unplanned P2

日期：2026-08-01 起

恢复入口：[`Handoff`](../handoffs/2026-08-01-v1.1.1-maintenance-versioning-next.md)

## 任务属性

- 来源：Owner 在 v1.1 发布收口后提出的非计划维护增强；
- 优先级：P2；
- 前置状态：`v1.1.0` 已通过 Codex 发布门禁并于 2026-08-01 正式发布；
- 当前阶段：先完成只读盘点、Spec、Plan，必要时新增 ADR，再按 TDD 实施。

## 目标

让更新历史 Skill 的用户可以明确区分 hotfix、feature 和 refactor；只让真正
阻断本次修改的问题阻止交付，把整体结构债务转入独立重构计划，并让普通
`improve` 建立可追踪的 SemVer、Changelog、维护记录和发布边界。

## 进入范围

- hotfix/feature/refactor 分类依据与确定性维护建议；
- `blocks_current_change`、`defer_to_refactor`、`informational` 分流；
- 按维护等级确定回归范围，同时保留共享安全与兼容硬门槛；
- current/target version、recommended bump、compatibility impact、
  release required 和 changelog entry；
- 旧 1.x plan/record 兼容读取、verify、history 和 undo；
- Git branch/worktree 建议，以及 Commit/Push/Tag/Release 独立批准边界。

## 不进入范围

- 把 `v1.1.1` 偷渡进 `v1.1.0` tag；
- 自动 Commit、Push、Tag、GitHub Release 或 Global/Profile 安装；
- Skill Creator、Superpowers、模型 Provider 或云服务运行时依赖；
- 创建后阅读、Skill Graph 或 2.0 Architecture Guardian 新功能。

## 任务

- [x] MV-0：非计划 P2 登记、Handoff、Task/Sprint/OB 入口对齐。
- [ ] MV-1：盘点维护、版本、schema、release/evolution 现有事实源。
- [ ] MV-2：完成 Spec、Plan；公开 1.x 契约变化时新增 ADR。
- [ ] MV-3：按 TDD 实现维护分级、债务分流、分级回归与版本闭环。
- [ ] MV-4：完成兼容、迁移、回滚、真实老 Skill 用例和独立评审。
- [ ] MV-5：完成全量门禁和发布文档同步，等待独立发布授权。

## 验证

- hotfix 可以在全局技术债存在时通过目标回归，并把非阻断债务延后；
- feature 建议 minor，并生成对应 Changelog 条目；
- 破坏公开 contract 的 refactor 建议 major，要求迁移、完整回归和独立分支；
- 安全、数据丢失、不可回滚、contract 破坏和漂移不能被延后；
- 无版本、非法版本和版本事实源冲突安全停止；
- 旧 1.x 记录继续读取、验证和撤销；
- 未获用户授权时没有 Commit、Push、Tag 或 Release。

## 退出条件

- Spec、Plan 和必要 ADR 完成；
- 实现、兼容、迁移、回滚、真实用例和独立评审完成；
- pytest、Ruff、Skill validation、production Doctor、portable self-test、
  credential lint、release consistency 和 diff check 全绿；
- README、Changelog、Roadmap、Task、Sprint、Version 和 Release Log 对齐；
- Commit、Push、Tag 和 GitHub Release 分别等待明确授权。
